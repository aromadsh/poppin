# 행사 분류 v1

## 표시 설명과 추천용 분류

`genre`는 기존의 상세 한국어 설명을 유지한다. 예: `미디어 리터러시 방탈출 체험`.

`classification`은 별도 데이터이며 대분류 1개, 그 대분류에 속한 소분류 1개, 독립적인 체험 방식 태그 최대 5개를 담는다. 고정 ID와 한국어 표시 이름은 `lib/event-taxonomy.ts`에서 관리한다. 운영 조건(예약·대기·영업시간·체류시간)은 분류에 넣지 않는다.

```json
{
  "version": 1,
  "category": "culture_education",
  "subcategory": "media_education",
  "experienceTags": ["escape_room", "puzzle", "hands_on"],
  "sourceUrls": ["https://example.com/event"]
}
```

위 URL은 형태를 보여주는 예시이며 실제 근거가 아니다.

## 대분류와 소분류

| 대분류 ID | 이름 | 소분류 |
| --- | --- | --- |
| beauty | 뷰티 | 스킨케어·메이크업·향수 |
| fashion | 패션 | 의류·가방·액세서리 |
| food | 음식·음료 | 피자·디저트·음료 |
| culture_education | 문화·교육 | 미디어 교육·미술·도서·음악 |
| entertainment | 엔터테인먼트 | 게임·캐릭터 |
| lifestyle | 라이프스타일 | 홈·리빙·문구·테크 |
| unclassified | 미분류 | 미분류 |

주제가 여러 개인 경우 대표 주제 하나만 선택한다. 소분류를 확인할 수 없거나 목록에 없으면 대분류만 유지하고 소분류는 `unclassified`로 둔다. 새 ID를 AI가 만들게 하지 않는다. 반복적인 미분류 사례를 검토한 뒤 목록을 코드로 확장한다.

체험 방식 태그는 방탈출·퍼즐·참여형·제품 체험·전시·쇼핑·시식·시음·포토존·워크숍·공연을 위한 고정 ID 목록이다. `시식·시음`은 하나의 `tasting` 태그다. 뷰티와 방탈출처럼 주제와 방식은 교차할 수 있다. 태그 미확인은 빈 배열이며, 확인되지 않았다는 것이 해당 체험이 없다는 뜻은 아니다.

## 처리 흐름과 근거

1. 자동 검색(`/api/lookup`)과 행사 조사(`/api/analyze`)의 기존 AI 응답에 같은 고정 분류 스키마를 추가한다. 분류를 위한 별도 API 요청은 만들지 않는다. 응답 필드가 늘어 토큰 사용량은 증가할 수 있다.
2. AI는 실제로 수집된 해당 행사 출처가 뒷받침하는 분류만 선택한다. 브랜드명이나 사용자 입력 설명만으로 분류를 추정하지 않는다.
3. 서버는 실제 검색 출처 목록과 URL을 대조한다. 행사 일치가 확인되지 않거나 분류 근거 URL이 없으면 전체를 미분류로 처리한다. 소분류의 부모도 코드로 검증한다. URL 대조는 출처 존재 확인이며 문서 내용의 의미를 독립적으로 재검증하는 것은 아니다.
4. 자동 검색 분류는 입력 상태에 보관하고, 이름·주소·장르·방문 기간 변경 시 초기화한다. 수동 장르/주소를 자동 결과로 덮어쓰지 않는다.
5. 행사 조사 단계에서 서버가 다시 수집한 근거로 분류한다. 클라이언트의 분류를 행사 검증 근거로 받지 않는다.
6. 기존 저장 응답에 분류가 없으면 미분류로 취급한다. 개발 QA(`/?qa=1`)에서 결과의 분류를 확인할 수 있다.

분류는 [취향 점수](taste-scoring.md)에 사용한다. 기존 일정 점수와 별도 계산하며 목적별 일정 우선순위 변경은 다음 구현 단계다. 현재 프로젝트에는 분류를 영구 저장하는 DB 기능이 없으며 분류는 API 응답과 화면 상태에 보관된다.
