# 팝업 입장 방식과 정보 누락 점검

## 실제 사례에서 확인한 범위

확인일은 한국 시간 2026-10-31이다. 아래 공개 자료 검토는 앱의 유료 AI 검색 결과를 재현한 실험이 아니며, 당시 실패 응답 원문을 확보한 것도 아니다. 현재 운영이나 입장을 보장하는 고정 데이터로 코드에 넣지 않는다.

## 이번 구현

1. 사전예약과 현장 입장을 독립된 정보로 반환하고 각각 출처를 검증한다.
2. 현장 입장 가능이 확인되면 미예약 또는 예약 매진 상태여도 현장 방문으로 계산한다. 사용자가 입력한 예약 시각은 기존 제약대로 유지한다.
3. 입장 정책 미확인은 확정 일정 대신 `conditionalDays`로 별도 계산한다. 명시적 입장 불가, 미보유 필수 예약, 매진 좌석, 운영 근거 부족을 임의로 허용하지 않는다.
4. 조건부 일정의 각 장소에 입장 방법·예약 필요 여부·입장 마감 확인 조건을 표시한다. 확정 일정과 혼합하거나 입장을 보장하지 않는다.
5. 이동·체류·대기 상한·다음 영업 시작 전 여유를 실제 일정 값으로 합산해 표시한다. 다른 순서 대비 절약량이나 실시간 대기시간을 새로 만들어 설명하지 않는다.

## 검증과 리뷰 범위

- 기존 자동입력·예약 완료·예약 후보·출처 검증을 포함한 무료 테스트 106개 통과.
- 타입 검사와 production build 통과. 화면 컴포넌트의 서버 렌더링 검증도 포함하지만 실제 브라우저의 클릭·모바일 시각 검증을 대체하지 않는다.
- 유료 API 호출이나 실제 예약 조회는 수행하지 않았다. 검색 성공률·예측 정확도 수치는 보고하지 않는다.
- 사용자 취소에 따라 목데이터용 API·화면은 추가하지 않았다. 자동 테스트 내부의 가짜 응답만 사용한다.
- 기존 통합 변경과 이번 기능 변경은 아직 커밋하지 않았다. 커밋별 승인과 변경 묶음을 별도로 검토해야 한다.

남은 검증은 운영자 원문 및 실제 검색 응답과의 대조, 입장 정책이 혼합된 실제 행사에서의 확인, 실제 브라우저 상호작용이다. 저장된 실제 AI 응답을 재생하는 개발 기능은 이 문서의 무료 테스트와 구분되며 아직 구현하지 않았다.
